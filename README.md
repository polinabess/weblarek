# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.


### Данные
В этом разделе описаны интерфейсы данных, разработанные в рамках разбора проекта. Они формализуют структуру сущностей, участвующих в бизнес‑процессах (продажа товаров, оформление заказа и т. д.), и обеспечивают типобезопасность при работе с данными в коде.

#### Интерфейс IProduct (Товар)
Назначение:
Интерфейс описывает структуру данных о товаре, используемую в каталоге и при отображении карточек товаров.

Описание полей:

- id — уникальный идентификатор товара (строка).
- title — название товара. Отображается в карточке товара, в результатах поиска и в корзине.
- description — подробное описание товара. Используется в детальной карточке товара.
- image — ссылка (URL) на изображение товара. Необходима для отображения картинки в каталоге, карточке и корзине.
- category — категория товара. Используется для группировки товаров в каталоге, фильтрации и навигации.
- price — цена товара.

interface IProduct {
  id: string;
  description: string;
  image: string;
  title: string;
  category: string;
  price: number | null;
}

#### Интерфейс IBuyer (Покупатель)
Назначение:
Интерфейс описывает данные покупателя, необходимые для оформления заказа.

Описание полей:

- payment - способ оплаты покупателем товара, описываемый типом TPayment - кастомный тип данных, имеющий только два строковых варианта или пустое значение. 
- email — электронная почта покупателя.
- phone — номер телефона покупателя.
- address — адрес доставки.

interface IBuyer {
  payment: TPayment;
  email: string;
  phone: string;
  address: string;
}


### Модели данных
В этом разделе описаны классы, реализующие работу с данными в системе. Каждый класс инкапсулирует состояние и поведение для конкретной предметной области (каталог, корзина, покупатель), обеспечивая управление данными, валидацию и базовые бизнес‑операции.

#### Класс Catalog (Каталог на главной)
Назначение и зона ответственности:
Класс управляет данными каталога товаров на главной странице. Отвечает за хранение списка товаров, выбор и сохранение карточки товара, а также за сохранение текущего состояния каталога.

Конструктор класса:
 constructor(initialProducts: IProduct[] = [], initialSelected?: IProduct)

Поля класса:

- products: IProduct[] — хранит полный список товаров каталога. Используется для отображения карточек, фильтрации и поиска.
- selectedProduct: IProduct | null — хранит ссылку на выбранную карточку товара. Необходима для отображения детальной информации, передачи в корзину и сохранения пользовательского выбора.
Методы класса:

- getProducts(): IProduct[] — возвращает текущий массив товаров.
- saveSelectedProduct(card: IProduct): void — сохраняет выбранную карточку товара. Входной параметр: card: IProduct.
- getSelectedProduct(): IProduct | null — возвращает текущую выбранную карточку или null, если ничего не выбрано. Тип возврата: IProduct | null.
- saveProducts(newProducts: IProduct[]): void — обновляет массив товаров в каталоге. Входной параметр: newProducts: IProduct[].
- getProductById(id: number): IProduct - получение одного товара по его id;

#### Класс Cart (Корзина с товарами)
Назначение и зона ответственности:
Класс реализует логику работы корзины: добавление и удаление товаров, подсчёт итоговой стоимости, проверку наличия товаров и управление количеством позиций.

Конструктор класса:
constructor(initialProducts: IProduct[] = [])

initialProducts: IProduct[] — опциональный начальный массив товаров в корзине (по умолчанию — пустой массив).

Поля класса:

- items: IProduct[] — хранит список товаров в корзине. Используется для отображения позиций, расчёта суммы и формирования заказа.

Методы класса:

- addProduct(product: IProduct): void — добавляет товар в корзину. Входной параметр: product: IProduct.
- removeProduct(product: IProduct): void — удаляет товар из корзины по его идентификатору.
- getQuantity(): number — возвращает количество товаров в корзине. Тип возврата: number.
- getItems(): IProduct[] — возвращает текущий список товаров в корзине. Тип возврата: IProduct[].
- calculateTotal(): number — пересчитывает и возвращает итоговую сумму стоимости товаров. Тип возврата: number.
- hasProduct(productId: string): boolean — проверяет наличие товара по его идентификатору. Входной параметр: productId: string. Тип возврата: boolean.

#### Класс Buyer (Покупатель)
Назначение и зона ответственности:
Класс управляет данными покупателя: хранит контактную и платёжную информацию, выполняет проверку корректности данных и обеспечивает их сохранение.

Конструктор класса:
constructor(data: IBuyer)

data: IBuyer — объект с начальными данными покупателя (email, телефон, адрес, платёжные данные).

Поля класса:

- payment: TPayment — хранит платёжные данные покупателя (тип TPayment). Используется для проведения транзакции и интеграции с платёжным шлюзом.
- email: string — электронная почта покупателя. Необходима для уведомлений, подтверждения заказа и коммуникации.
- phone: string — номер телефона покупателя. Используется для оперативной связи и подтверждения доставки.
- address: string — адрес доставки или адрес для выставления счёта. Требуется для формирования заказа и передачи в службу доставки.

Методы класса:

- Методы установки: 
  - setPayment(payment: TPayment): void - установка типа оплаты.
  - setEmail(email: string): void - установка email пользователя.
  - setPhone(phone: string): void - установка номера телефона.
  - setAddress(address: string): void - установка адреса.

- validate(): Record<keyof IBuyer, string> | {} — выполняет валидацию всех полей. Не принимает параметров. Возвращает объект ошибок.
Если поле пустое (null или пустая строка), в результирующем объекте появляется запись вида { fieldName: 'Текст ошибки' }.
Если поле валидно, оно отсутствует в результирующем объекте.
Тип возврата: Record<keyof IBuyer, string> | {} (объект, где ключи — имена полей интерфейса IBuyer, а значения — тексты ошибок; либо пустой объект, если ошибок нет).
- getData(): IBuyer — возвращает текущие данные покупателя в виде объекта IBuyer. Тип возврата: IBuyer.
- clearData(): void — сбрасывает все данные покупателя в исходное состояние (null). Не принимает параметров.

Представитель коммуникационного слоя — он будет отвечать за получение данных с сервера и отправку данных на сервер. При работе будем использовать функциональность класса API.

Поля класса:
- private api: Api - поле для хранения экземпляра Api.

Конструктор класса:
constructor(api: Api)

api: Api - экземпляр класса Api

Методы класса:
- getProducts(): Promise<IProduct[]> - получает с сервера данные продуктов
